## Description

Build on CMR-008. Replace the single save slot with 3 named slots + an autosave slot. Title screen lists them with timestamp + colony name. On corruption, the slot loads the previous good snapshot if available.

## Domain Brief

**What**: Map the existing single-slot autosave to a 3-named-slots + autosave UI on the title screen, and make every load self-heal from a one-generation backup when the active blob is corrupt.
**Why**: Players currently lose all progress if the autosave row is truncated or IndexedDB writes a partial blob; alpha testers have no way to keep more than one colony.
**As-Is → To-Be**:
- As-Is: `saveGame/loadGame` write one raw `SaveDoc` per `slotId`; HUD hard-codes `'autosave'`; TitleScreen has no Continue list; no CRC, no fallback.
- To-Be: store wraps each doc in `{payload, crc}`, rotates `<slot>__prev` on write, falls back on CRC mismatch; TitleScreen renders 4 rows (autosave + slot1..3) with colony name, day, and last-saved time.

Key facts the implementer must know:

- Current API surface lives in `src/game/Sim/Saves/store.ts:26` (`saveGame`), `:46` (`loadGame`), `:53` (`listSaves`); rename/extend rather than parallel-implement.
- `SaveMeta` already carries `name`, `savedAt`, `day`, `seed` (schema.ts:54). Only delta needed: add `colonyName: string`.
- `Game.applyLoaded` (Game.ts:132) is the existing load-path swap; reuse it. The post-load `window.__crittermoorApplyLoad` global (Game.ts:65) is fine to keep but TitleScreen should call a typed `Game.loadFromSlot(slotId)` instead of touching `window`.
- CMR-008 commit `4e2ccbc` only edited the kanban file — there is **no** existing CRC code in the repo (verified grep). Implement FNV-1a inline (~10 LoC, no dep).
- CMR-030 is queued to bump `SaveDocV4`; keep CRC outside `SaveDoc` (in an envelope) so this ticket does **not** touch `migrations.ts`.
- `tests/sim/saves.test.ts` runs under `happy-dom` (vite.config.ts:39). Confirm IDB availability in Plan; if absent, add `fake-indexeddb/auto` import to the test file (one line, dev-dep only).

## Plan

**What**: Pick **Option A** and lock the implementation contract — envelope-wrap each slot, FNV-1a CRC, rotate `<slot>__prev` in one IDB transaction, no `SaveDoc` version bump.
**Why**: Smallest blast radius (7 source files + 1 test file), zero overlap with CMR-030's pending `SaveDocV4`, and CRC matches the AC text verbatim.
**As-Is → To-Be**:
- As-Is: `saveGame/loadGame` per single slot; no envelope, no CRC, no `__prev`, no TitleScreen Continue list.
- To-Be: `saveToSlot/loadSlot/listSlots` with envelope + CRC + rotation; TitleScreen renders autosave + 3 named rows; HUD surfaces CRC fallback warning.

- Approach: envelope `{ version:1, payload: SaveDocV3, crc:number }`; payload migration stays in `migrations.ts` (untouched). Inline FNV-1a (≤10 LoC) — no new file.
- Module scope (write-only here): `schema.ts` (types + slot constants), `store.ts` (new API + rotation + legacy-blob branch), `Game.ts` (`loadFromSlot`), `App.tsx` (onContinue wiring), `TitleScreen.tsx` (colony-name input + 4 slot rows), `HUD.tsx` (re-wire to `saveToSlot(AUTOSAVE_SLOT,…)` + warning surface), `tests/sim/saves.test.ts` (4 new tests), `package.json` (`fake-indexeddb` devDep).
- Contracts: `saveToSlot(slotId, sim, { name?, colonyName }) -> SaveMeta`; `loadSlot(slotId) -> Promise<{ sim, source: 'active' | 'prev', warning? } | null>`; `listSlots()` filters `__prev` suffix. Throws `SaveCorruptError` when both active and `__prev` are unusable.
- Steps (ordered, each verifiable): 1) add `fake-indexeddb` devDep & install; 2) write the CRC-fallback RED test; 3) extend `schema.ts`; 4) rewrite `store.ts` (envelope+CRC+rotation+legacy branch); 5) re-wire `HUD.tsx`; 6) add `Game.loadFromSlot`; 7) wire `App.tsx` onContinue + render TitleScreen rows; 8) add remaining 3 tests; 9) `npm run verify` green.
- Risk / rollback: legacy single-blob autosave handled by ≤6 LoC defensive branch in `loadSlot`. `DB_VERSION` stays at 1 — no IDB upgrade hazard. Revert is a single feature-commit revert.
