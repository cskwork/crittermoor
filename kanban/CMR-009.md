## Plan Candidates

**What**: Three ways to thread audio cues out of the sim and around the UI.
**Why**: The wiring choice fixes how mockable, testable, and pure the sim stays.

- A — Thread `sfx.play` via `SimHooks` (mirrors `jobs.requestPath`, `raid.onRaid`): smallest blast radius, fully mockable in tests, sim stays pure. Files: tick.ts + 4 system files + Game.ts + UI screens. Test: pass `vi.fn()` to `makeJobSystem`.
- B — Global `SoundManager` singleton imported everywhere: shortest code, but `src/game/Sim/**` now imports a UI/runtime module — breaks the layering rule in `docs/architecture.md` §1, harder to mock without `vi.mock`.
- C — Append structured cues to `sim.events` and drain in UI per tick: keeps sim pure but reuses a text-log channel for typed audio data; couples ordering to log writes, awkward for tests asserting "exactly one chop_wood".

## Recommendation

**What**: Go with Option A — thread `sfx.play` through `SimHooks`; SoundManager owns Howler + volume + persistence; BattleScreen/Toolbar/TitleScreen call SoundManager directly.
**Why**: Matches existing hook pattern, preserves sim purity, mockable without `vi.mock`.
**Risks accepted**: small refactor to `behavior.ts` (wrap with `makeBehaviorSystem`); BattleScreen log-scan must use stable substrings (`'crit'`, `'used'`) — covered by snapshot of `BattleSim.ts:60-62` format.
**First failing test** (drives implementation): `chop job calls sfx.play('chop_wood') exactly once when a designation completes` in `tests/audio/SoundManager.test.ts` — builds a sim, sets `Skills.construct` high, places a chop designation adjacent to a warden, advances ticks past `WORK_TICKS_CHOP` via `makeJobSystem({ requestPath: noop, sfx: { play } })`, asserts `play.mock.calls.filter(c => c[0] === 'chop_wood').length === 1`.
