## Description

Wardens currently auto-pick the nearest designation with no user control. Add the RimWorld-style priority grid: each warden has an 8-slot priority array indexed by `WorkType` enum (`Chop, Mine, Construct, Cook, Haul, Plant, Doctor, Clean`). Values 0..4 where `0 = disabled`, `1 = highest`, `4 = lowest`. Job and construct assignment must iterate work types in priority order (1 -> 4) and skip disabled.

This is the foundation that every later worktype (CMR-034..CMR-037) plugs into. Do NOT introduce new job kinds in this ticket - only the priority mechanism over the existing Chop / Mine / Construct work.

## Acceptance Criteria

- New `WorkPriority` bitecs component in `src/game/Sim/components.ts` with 8 ui8 slots (one per `WorkType`).
- New `WorkType` enum in `src/game/Sim/systems/workTypes.ts` (Chop=0, Mine=1, Construct=2, Cook=3, Haul=4, Plant=5, Doctor=6, Clean=7).
- New warden default priorities: Chop=2, Mine=2, Construct=2, others=3. Construct work in `systems/construct.ts` and chop/mine in `systems/jobs.ts` only assign work if `WorkPriority[type] > 0`.
- Selection algorithm: iterate priorities 1->4 within a single tick; for each priority level, pick the best (skill+distance) eligible job across the work types that share that level. Higher level (lower number) ALWAYS wins.
- Save schema bump to v4 with backfill: legacy v3 saves default new wardens to the priority defaults above.
- Tests in `tests/sim/priority.test.ts`: (a) priority=0 disables work type; (b) priority=1 beats priority=4 on equal distance; (c) within same priority, distance/skill tiebreak preserved; (d) save v3 -> v4 migration adds defaults.
- `npm test`, `npm run typecheck`, `npm run lint` all green.
