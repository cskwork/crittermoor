## Description

Generalize CMR-002's auto-cook into a RimWorld-style bill list attached to workstation structures (Stove, eventually Bench/Lab). A bill is a recipe + a stop rule (`do x times` | `do until count < N` | `forever`). The job system iterates active bills on each workstation in order; the first bill whose stop rule is not satisfied becomes a job.

After this ticket lands: Stove defaults to one bill `Cook Meal until meals<10`, but the user (UI in CMR-040) can add/remove/reorder bills.

## Acceptance Criteria

- New module `src/game/Sim/systems/bills.ts` with types:
  - `Recipe = { id: 'cook_meal'; inputs: [{kind:ItemKind.Wood,count:2}]; outputs: [{kind:ItemKind.Meal,count:1}]; workTicks: number }`
  - `Bill = { recipeId: string; rule: { kind:'until'; itemKind:ItemKind; threshold:number } | { kind:'count'; remaining:number } | { kind:'forever' } }`
- Per-Stove bill array stored on `sim.bills: Map<workstationEid, Bill[]>`.
- Cook job (introduced or extended from CMR-002) consumes inputs from in-stockpile items, runs `recipe.workTicks`, produces outputs as ItemStacks on the workstation tile (or adjacent stockpile if available).
- Default Stove receives `{ recipeId:'cook_meal', rule:{kind:'until', itemKind:Meal, threshold:10} }` on construct completion.
- Save migration persists bills.
- Tests in `tests/sim/bills.test.ts`: (a) bill produces meals until threshold; (b) `count` rule decrements and stops; (c) bill with missing inputs is skipped, not crashed; (d) reorder changes which bill fires first.
- `npm test`, `npm run typecheck`, `npm run lint` all green.
