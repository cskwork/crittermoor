## Description

Critters have `level` and `xp` fields but no gain. Award XP on battle victory:
xp_gain = max(1, defeated.level * 4 + bond * 0.5). Level up when `xp >= level * 50`. At levels 5 and 10, unlock the next move from the species' learnset.

## Acceptance Criteria

- New `gainBattleXP(critter, defeatedLevel)` helper; called by BattleSim on each KO.
- Species data gets a `learnset: { level: number; moveId: string }[]` array; existing 6 species each get 2 entries (lv5 + lv10) chosen from the 16-move pool by type fit.
- On level up: persist xp/level in Critter SoA + event log ("<name> reached level X").
- Test: BattleSim run with a controlled outcome confirms xp + level + unlocked move; replay deterministic with same seed.
- Save v3 already encodes Critter; if learnset progress needs to persist, add a learnedMoves[] field with v3 migration.
- `npm test`, `npm run typecheck`, `npm run lint` green.

## Domain Brief

**What**: Map how XP, levels, and per-species learnsets fit the current battle code so the implementer can wire them in without reshaping core systems.
**Why**: Battle has stat scaling but no progression — bonded critters stay flat forever, undermining the tame → grow loop the game's roadmap is built on.
**As-Is → To-Be**:
- As-Is: `BattleCritter` is a transient clone with no XP field; `Critter` SoA stores level/xp but nothing writes to them; no learnset on species.
- To-Be: KOs award XP into the in-fight critter, level-ups unlock the species learnset entry, and the result commits back into `Critter` SoA (with `learnedMoves[]` persisted in save v3).

- Battle layer is decoupled from ECS: `BattleCritter` (`src/game/Sim/Battle/BattleState.ts:5-19`) has no `eid`, so XP credit must round-trip via a new `sourceEid?` field set by `teamFromSpecies`/`buildBattleCritter` (`src/game/Sim/Battle/buildTeam.ts:6-38`) and committed in `Game.endBattle` (`src/game/Game.ts:117-130`).
- KO hook lives at `src/game/Sim/Battle/BattleSim.ts:59-63` — when `def.hp` drops to 0, the actor (`atk`) earns `xp_gain = max(1, def.level * 4 + bond * 0.5)`. `BattleCritter` does not carry `bond` today; either add it or pass it through.
- Save v3 already carries critter snapshots (`src/game/Sim/Saves/schema.ts:3-14`) and migration uses additive spreads (`src/game/Sim/Saves/migrations.ts:23-30`). Adding optional `learnedMoves?: string[]` needs no version bump — older v3 saves read as empty arrays.
- Move pool is 16 moves over 8 types in `src/game/Sim/Battle/moves.ts:18-43`; each species's existing `movePool` already covers up to 4 of these. "By type fit" lv5/lv10 picks may overlap with `movePool`.
- World-facing event log is `sim.events: string[]` (`src/game/Sim/world.ts:36`), used by `tame.ts:49` and `raid.ts:47`. Level-up messages belong here, not in `state.log` (which is dropped with the battle).
- Determinism is RNG-driven (`src/shared/rng`); `gainBattleXP` MUST be pure integer math — never call `rng.chance` or `rng.int`.

## Plan

**What**: Add a pure XP helper, extend `BattleCritter` / `SpeciesDef` / `BattleState`, hook the KO branch, persist via a commit boundary in `Game.endBattle`, and store `learnedMoves` as an additive v3 save field — plus a deterministic test that replays identically.
**Why**: Keeps BattleSim layer-pure and deterministic; raid-path persistence becomes a one-line follow-up (attach `sourceEid` to player teams) without re-architecting anything.
**As-Is → To-Be**:
- As-Is: Battle ends; xp/level/learnedMoves never persist; no learnsets.
- To-Be: Winning side's `sourceEid`-bound critters write xp/level/learnedMoves into ECS + save; level-ups emit `sim.events`; deterministic replay green.

1. `species.ts`: add `learnset?: readonly { level: number; moveId: string }[]`; populate all 6 species (lv5/lv10 table in `docs/CMR-006/plan/implementation-plan.md`).
2. `BattleState.ts`: extend `BattleCritter` with optional `xp`, `bond`, `learnedMoves`, `sourceEid`; add `worldEvents?: string[]` to `BattleState`; clone arrays in `cloneCritter`.
3. `buildTeam.ts`: extend `buildBattleCritter(species, level, opts?)` for ECS-sourced fields; merge `learnedMoves` into `moves` (dedupe, cap 4); add `buildBattleCritterFromEid(sim, eid, lvl?)`.
4. **New** `src/game/Sim/Battle/xp.ts`: pure `gainBattleXP(c, defeatedLevel)`; integer math (`Math.floor(defeatedLevel*4 + bond*0.5)`, min 1); `while` loop for multi-level KOs; returns level-up event strings; `commitBattleXP(sim, c)` writes ECS + `sim.learnedMoves`.
5. `BattleSim.ts:59-63`: after `def.hp` clamps to 0, call `gainBattleXP(atk, def.level)`; append events to `next.worldEvents` and `next.log`.
6. `Game.endBattle`: new `commitBattleResults(state, winner)` flushes `worldEvents` to `sim.events` always; commits xp/level/learnedMoves only for `winner` side's `sourceEid`-bound critters.
7. `world.ts`: add `learnedMoves: Map<number, string[]>` (mirrors `paths`/`blueprints` external-storage pattern); `createSimWorld` initializes empty.
8. Save: extend `EntitySnapshot.critter.learnedMoves?` (additive, no migration row); `codec.ts:55-62` serialize from `sim.learnedMoves`; `codec.ts:135-138` deserialize back into the map.
9. `tests/sim/battle.test.ts`: add two `it` blocks for KO-XP + lv5 unlock + replay determinism (verbatim test body in `docs/CMR-006/plan/implementation-plan.md`).
10. Verify `npm test && npm run typecheck && npm run lint`. Any failure → root-cause; do NOT silence or edit tests to fit a broken impl. Stop conditions and full file scopes live in the details file.

## Learnings

**What**: Distilled what CMR-006 taught about layering ECS writes around the transient battle layer.
**Why**: Future combat/raid tickets need a clear contract for "where does progression actually persist" so they don't re-derive the wiring or break determinism.
**As-Is → To-Be**:
- As-Is: pattern existed implicitly (`paths`/`blueprints` sidecars, save v3 spread); never documented as a reusable shape.
- To-Be: two wiki entries codify the commit-boundary and sidecar+save patterns.

- BattleSim must stay layer-pure — write to ECS only at `Game.commitBattleResults` keyed off `BattleCritter.sourceEid`. Anything that needs to survive past `endBattle` flows through `worldEvents` or the commit step.
- Variable-length per-critter data (`learnedMoves`) cannot live in a bitecs SoA column; the project's working pattern is `Map<eid, T>` on `SimWorld` mirrored by an optional save-field — no migration row needed when the field is additive on the current version.
- Determinism survives because XP math is pure integer arithmetic; mixing in any `rng.*` call here would silently break replay equality with the same seed.
- Known follow-ups (Review LOW): `triggerRaid` / `startTestBattle` still call `teamFromSpecies` without `sourceEid`, so raid XP is dropped on the floor today; `buildBattleCritterFromEid` is scaffolded but uncalled — wire both up before raids are expected to feel rewarding.
