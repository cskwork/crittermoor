## Description

Depends on CMR-031 (WorkPriority) and CMR-032 (Schedule). Build the React panel that lets the user actually edit the priority grid and the daily schedule for each warden - the user-facing payoff of the foundation tickets.

Panel toggled by hotkey `P`. Two tabs: Work (grid: rows=wardens, cols=work types, cells=priority 0-4, click cycles 0->1->2->3->4->0) and Schedule (grid: rows=wardens, cols=24 hours, cells=slot kind, click cycles Anything->Work->Sleep->Joy->Anything).

## Acceptance Criteria

- New `src/ui/panels/PriorityPanel.tsx` rendered inside the colony screen. Hotkey `P` toggles visibility (`src/ui/InputController.tsx`).
- Work tab reads `WorkPriority` component and writes back to it; cell color indicates priority (1=green, 2=light-green, 3=yellow, 4=orange, 0=red-strike).
- Schedule tab reads `Schedule` and writes back; columns labeled 0..23; default new wardens visible.
- Disabled cells (priority=0) are visually distinct and skipped by job assignment (already enforced by CMR-031).
- Save / load roundtrip preserves user edits (already covered by CMR-031/CMR-032 schema bumps; this ticket only verifies the UI does not corrupt state).
- Tests in `tests/ui/priorityPanel.test.tsx` (Vitest + Testing Library): (a) click cycles priority; (b) `P` hotkey toggles panel; (c) editing one warden does not bleed into another.
- `npm test`, `npm run typecheck`, `npm run lint`, `npm run build` all green.
