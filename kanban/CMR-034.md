## Description

`sim.resources.wood` and `sim.resources.stone` are abstract counters. Replace the chop / mine "instant credit" with physical item stacks dropped on the source tile, and add a `Stockpile` designation that marks tiles as "items should live here". This ticket only covers the spawn-and-zone half - the hauling job that moves items into the zone is CMR-035.

After this ticket lands: chopping a tree drops `ItemStack{kind:Wood,count:2}` on the tree tile and does NOT touch `sim.resources`; only items physically inside a Stockpile zone count toward the colony total used by Cook / Build.

## Acceptance Criteria

- New `ItemStack` bitecs component `{ kind: ui8, count: ui16 }` and enum `ItemKind { Wood=1, Stone=2, RawFood=3, Meal=4 }`.
- New `sim.stockpiles: Map<key, { tx: number; ty: number }>` (key = `ty * width + tx`).
- New "stockpile" tool/designation in `src/game/Sim/Designations.ts` (paint a tile rectangle as Stockpile); persisted in saves.
- `sim.resources` now derives from "items in stockpiles": helper `countItems(sim, kind)` returns the sum of `ItemStack.count` on tiles that are inside any Stockpile. The Resources HUD reads via this helper.
- Chop / Mine completion in `systems/jobs.ts` spawns an `ItemStack` entity on the source tile instead of `sim.resources.wood += 2`.
- Save schema bump (one higher than the current head): persist items + stockpiles. Legacy saves convert abstract `resources.wood / stone` into a single auto-Stockpile at origin spawn with seeded stacks (so the user does not lose materials).
- Tests in `tests/sim/items.test.ts`: (a) chop spawns ItemStack on tile; (b) item inside Stockpile counts toward `countItems`; (c) item outside Stockpile does NOT count; (d) legacy save migration produces matching counts.
- `npm test`, `npm run typecheck`, `npm run lint` all green.
