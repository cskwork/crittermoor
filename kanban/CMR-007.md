## Description

Today the behavior system picks jobs purely on distance + skill. Add a per-warden Priority Matrix UI where each row is a warden and each column is a job category (chop, mine, haul, build, cook, tame, fight, sleep). Cells take 0..4 (0 = disabled). The job system multiplies the score by (5 - priority) and skips priority=0.

## Acceptance Criteria

- New panel `src/ui/panels/PriorityMatrix.tsx` reachable from a toolbar tab; renders a 3x8 grid for the 3 wardens.
- New SoA `WorkPriority` with default 2 across the board; persists in save v3 (additive, falls back to default 2 for legacy saves).
- Behavior + job assignment multiply by priority in `src/game/Sim/systems/behavior.ts`.
- Tests in `tests/sim/behavior.test.ts` confirm priority=0 prevents the warden from picking that job; priority=4 wins over distance ties.
- Determinism preserved.
- `npm test`, `npm run typecheck`, `npm run lint` green.

## Domain Brief

**What**: Add a per-warden RimWorld-style work priority table (3 wardens × 8 categories, values 0..4) wired into the autonomous job picker so players can steer who does what.
**Why**: Today every warden chases the same nearest designation; players cannot specialise wardens or shut a category off, which blocks the "core-loop" goal of meaningful colony management.
**As-Is → To-Be**:

| A | Literal `score *= (5 - priority)` + `if p===0 continue`. Smallest diff but priority=4 → ×1 contradicts "priority=4 wins"; tests fail. | `src/game/Sim/systems/jobs.ts:72` | none |

## Recommendation

Go with **Option B**. It preserves the existing `score > best.score` selection contract, satisfies both `priority=0 → skipped` and `priority=4 → wins over distance ties` directly, and limits the change in `behavior.ts` to a single guard before the `rest <= REST_LOW` transition. Surface the spec ambiguity (text says `(5 - priority)`; test says priority=4 wins) in `## Plan` so reviewers see the deliberate choice. First failing test the implementer writes:

## Plan

**What**: Add a per-warden 3×8 work-priority table (values 0..4) and wire 4 of the 8 categories into the autonomous job picker, so players can disable or boost specific work types per warden.
**Why**: Without it the colony-management core loop is flat — wardens cannot be specialised, idle wardens chase the same designation, and players cannot pause one work type while leaving others active.
**As-Is → To-Be**:
- As-Is: `jobs.ts:assignBestDesignation` and `construct.ts` pick targets purely on `skillBonus - distance`; `behavior.ts:33` auto-sleeps unconditionally; saves carry no priority data.
- To-Be: `WorkPriority` SoA (default `2`) gates and weights `chop`/`mine` (multiplier), gates `build`, and gates the sleep auto-switch; a `PriorityMatrix` panel edits live values; save v3 carries the field additively with a `2`-fallback for legacy saves.

**Approach**: Option B. `if (priority === 0) continue; score *= priority` in `jobs.ts:58-83` preserves the `score > best.score` contract and satisfies both ACs (0 skips, 4 multiplies a higher score so it wins ties). `construct.ts:26-50` gets gate-only `if (WorkPriority.build[eid] === 0) continue` at the top of the warden loop — no multiplier because each warden picks at most one blueprint per tick (no intra-warden tiebreaker exists). `behavior.ts:33` wraps `rest <= REST_LOW` in `WorkPriority.sleep[eid] !== 0`. Spec ambiguity (ticket says `(5 - p)`, test says priority=4 wins): the test wins; `score *= priority` is the deliberate choice.

**Ownership / write scope**: `components.ts` (define), `world.ts` (`spawnWarden` seeds 2s), `systems/jobs.ts` + `systems/construct.ts` + `systems/behavior.ts` (consumers), `Saves/schema.ts` + `Saves/codec.ts` (additive — no `SAVE_VERSION` bump), `stores/uiStore.ts` (`priorityPanelOpen`), new `ui/panels/PriorityMatrix.tsx`, `ui/panels/Toolbar.tsx` (toolbar tab below existing rail — not a `ToolMode` entry), `tests/sim/behavior.test.ts` (new `describe('work priority gating')`).

**Ordered steps** (1) define `WorkPriority` + `WORK_CATEGORIES`; (2) seed defaults in `spawnWarden`; (3) consumers in `jobs.ts`/`construct.ts`/`behavior.ts`; (4) add tests (must fail before step 3 lands, pass after); (5) save extension; (6) `uiStore` flag; (7) `PriorityMatrix.tsx`; (8) `Toolbar.tsx` tab + mount; (9) green `npm test` + `npm run typecheck` + `npm run lint`; (10) manual smoke (open panel, edit, save+reload).

**Verification**: `npm test` (all + new priority cases), `npm run typecheck`, `npm run lint`, manual `npm run dev` smoke. Determinism check: re-load a save twice and confirm identical RNG state — `WorkPriority` is player-controlled SoA, no RNG.

**Risks / rollback**: setting `sleep=0` lets `Needs.rest` decay indefinitely (player's call, RimWorld parity). Fallback if reviewer rejects sleep gate: drop the `behavior.ts` change and keep only the `score *= priority` half — still satisfies both stated ACs.

## Plan Adjustment

`score = baseScore * priority` flips sign when `baseScore` is negative (unskilled warden + far target), so priority=4 produced a worse score than priority=1.
