## Description

Currently `BattleScreen.tsx` enemy turns pick the first available move (line ~35). Replace with a deterministic scoring function:

score(move) = expectedDamage(move, attacker, target) + statusBonus(move) - selfRiskPenalty(move)

where expectedDamage uses the existing type chart and damage formula, statusBonus rewards inflicting a status the target does not already have (+20), and selfRiskPenalty subtracts 15 if the move would KO the attacker via recoil. Ties broken by seeded RNG.

## Acceptance Criteria

- New `pickEnemyMove(attacker, allies, enemies, rng)` in `src/game/Sim/Battle/ai.ts` returns the chosen move id.
- BattleScreen uses pickEnemyMove on enemy turn instead of `enemy.moves[0]`.
- Property test (fast-check) in `tests/sim/battle.test.ts` asserts: for any seed and rosters, the picked move's score is the maximum.
- Determinism preserved: same seed + state => same pick.
- `npm test`, `npm run typecheck`, `npm run lint` green.

## Domain Brief

**What**: The enemy in turn-based battles always picks its first move; we need it to score moves and pick the best one.
**Why**: Predictable enemies undercut the type-chart strategy the player just learned; smarter picks make encounters feel earned without changing balance numbers.
**As-Is → To-Be**:
- As-Is: `BattleScreen.tsx:35,45` reads `activeEnemy.moves[0]` regardless of types, HP, or status.
- To-Be: BattleScreen calls a pure `pickEnemyMove(...)` that ranks moves by expected damage + status bonus − self-risk and breaks ties via seeded RNG.

Code anchors the implementer must read first:
- `src/game/Sim/Battle/damageFormula.ts:26-35` — base formula `((2L/5+2)*power*a/d)/50 + 2`; sampled factors live at lines 30 (crit) and 37 (random).
- `src/game/Sim/Battle/typeChart.ts:24-26` — reuse `typeMultiplier` verbatim.
- `src/game/Sim/Battle/BattleSim.ts:64` — status only applies when `def.status === null`; mirror that gate in `statusBonus`.
- `src/shared/rng.ts:32` — `rng.int(n)` for the tie-break; caller must clone the sim RNG to keep `state.rngState` untouched.

Invariants and gotchas:
- `MoveDef` has no `recoil` field today (`moves.ts:6-16`); `selfRiskPenalty` returns 0 until one ships — keep the function in place so the formula stays honest. Recoil check is a no-op stub, not removed.
- Scorer must be RNG-free (only tie-break uses RNG) so the property test can recompute the max score deterministically.

## Recommendation

**What**: Go with Candidate A — pure `pickEnemyMove` in `src/game/Sim/Battle/ai.ts`, called from `BattleScreen.tsx`.
**Why**: Matches the AC signature exactly, keeps the sim contract untouched, and the deterministic-score property is trivially testable.
**Risks accepted**: AI ignores speed/turn order (depth-1 lookahead deferred); `selfRiskPenalty` is dormant until a `MoveDef.recoil` field exists.
**First failing test** (paste verbatim into `tests/sim/battle.test.ts`, expect ImportError until `ai.ts` lands):

```ts
import { pickEnemyMove, scoreMove } from '@/game/Sim/Battle/ai'
it('picks the move with the maximum score', () => {
  fc.assert(fc.property(fc.integer({min:1,max:1<<30}), (seed) => {
    const attacker = mk(20, 70, 50, 60, [CritterType.Fire, null], ['ember','cinder_dash','bite'])
    const target   = mk(20, 50, 50, 50, [CritterType.Plant, null])
    const pickedId = pickEnemyMove(attacker, [attacker], [target], createRng(seed))
    const scores   = attacker.moves.map(id => scoreMove(getMove(id)!, attacker, target))
    const max      = Math.max(...scores)
    const pickedScore = scoreMove(getMove(pickedId)!, attacker, target)
    return pickedScore === max
  }), { numRuns: 50 })
})
```

- To-Be: AI scores against the currently-active opposing critter; a 2-team regression test (`activeSlot !== 0`) protects this in `tests/sim/battle.test.ts`.

## Learnings

**What**: The scorer-as-pure-function approach held end-to-end; the only real surprise was an off-by-team-slot bug that briefly made the smart AI dormant after a player switch.
**Why**: Capturing the slot-aware invariant and the rewind reasons protects the next AI ticket (e.g. recoil moves, speed-aware lookahead) from re-inventing wheels or repeating the same regression.
**As-Is → To-Be**:
- As-Is: No durable note explained why `pickEnemyMove` must target the on-field defender or why `selfRiskPenalty` ships as a typed stub.
- To-Be: `docs/llm-wiki/battle-enemy-ai.md` pins both invariants in the Decision log with the path:line anchors a future agent needs.

- The scorer must target `enemies[0]` *which the caller chooses to be the active defender* — passing the whole team silently regresses to slot-0 targeting (HIGH finding in this ticket; fixed by passing `[activePlayer]` from BattleScreen, pinned by the active-slot regression test at `tests/sim/battle.test.ts:160-171`).
- "Expected damage" needs the *expected values* of the crit and random multipliers (`E_CRIT=1.03125`, `E_RAND=0.925`), not samples — sampling would consume RNG and break the property test's "score == max" invariant.
- `selfRiskPenalty` was kept as a typed `0`-stub rather than deleted; the formula stays honest and the next recoil-move ticket only needs to add the field, not re-introduce the function.
- The `[no-test]` commit on this branch (`5863d44`) is exempt — it only added host-backed Symphony symlinks (`.claude`, `docs/symphony-prompts`, `skills`), not prod code; the prod commit (`cb5c21e`) pairs `ai.ts` + `BattleScreen.tsx` + `.eslintrc.cjs` with `battle.test.ts` in one commit, no marker.
- Lint blocker pattern: the `skills/` template tree carries `@typescript-eslint/no-explicit-any` warnings that trip `--max-warnings=0`. Project rule is now `ignorePatterns: [..., 'skills']` in `.eslintrc.cjs:19` (same intent as the existing `generated` exclusion). Future template tooling should land under `skills/` or pick up that pattern.
