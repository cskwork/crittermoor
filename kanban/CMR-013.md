Every 6-10 in-game days a Traveling Tamer NPC arrives at the map edge for 2 days, offering 2 species not currently owned by the colony at a price (wood + stone). UI panel lets the player buy with current resources; on purchase, the critter spawns tamed at the colony center with bond=10.

## Domain Brief

**What**: A wandering NPC will visit the colony every few in-game days and offer to sell rare critters for wood and stone — like a travelling merchant in a colony sim.
**Why**: Lets players acquire species they have not encountered in the wild and gives wood/stone a second sink beyond construction.
**As-Is → To-Be**:
- As-Is: Only the `raid` event scheduler exists; no NPC visitors, no trade UI, no critter purchase path.
- To-Be: A trader scheduler with arrival/depart phases, a modal listing 2 offers, deterministic roster, save v4 persistence.

- Determinism contract: all randomness via `sim.rng` (`src/shared/rng.ts:14`); never `Math.random`. Save embeds `rngState` (`src/game/Sim/Saves/codec.ts:84`), so replays are bit-stable.
- Event scheduler precedent: `raid.ts:17-55` attaches `_raid` to `SimWorld` via a typed-cast mixin and exposes `ensure/get/set` helpers — the trader will mirror this shape in a sibling `trader.ts` so each system stays single-purpose (codebase convention: one system per file in `src/game/Sim/systems/`).
- Save schema is v3 (`schema.ts:1`); persisting trader state requires a v3→v4 migration in the existing chain (`migrations.ts:23-30`).
- Player-owned species check: `defineQuery([Critter, FactionComp])` filtered by `FactionComp.id === Faction.Player`, collecting `Critter.speciesId` into a `Set<number>`. Species pool = ids 1..6 (`species.ts:25-93`).
- Critter purchase = wild→player conversion proven in `tame.ts:44-49` (set `Faction.Player`, removeComponent `Wild`, addComponent `Bond`, set `Bond.level`); ticket specifies `bond=10` (note: tame uses 20).
- "Colony center" is not stored — anchor spawn to the first Player warden's tile via `playerQuery` (`Game.ts:19`); fall back to map midpoint if no warden exists.

**What**: One save/load consistency bug — bought critters lose their bond and keep a stale wild flag after a save → load round-trip — plus three deferrable LOW notes.
**Why**: A player who paid wood + stone for a tamed critter, then saves and reloads, finds their purchased critter is no longer bonded. Gameplay-visible regression that the existing tame path does not have.

- To-Be: Bond survives save/load for trader-bought critters, `Wild` is removed, and a regression test pins the behavior.

## Implementation (review rewind 1)

**Why**: Without this, a player who buys a critter, saves, and reloads finds the critter unbonded and still tagged Wild — exactly the MEDIUM regression Review flagged.

- To-Be: `partnerEid === 0` short-circuits remap and stays 0; `Bond` is re-added, `Wild` is removed, `Faction.Player` is set. New regression test pins the behavior.

- `src/game/Sim/Saves/codec.ts:157-176` — second-pass Bond resolver now branches: `partnerEid === 0` keeps the value, otherwise it looks up `eidRemap`. Same continue-on-undefined behavior preserved for genuinely missing partners.
