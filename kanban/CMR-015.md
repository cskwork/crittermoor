## Description

BattleScreen is functional but flat. Tween HP bars over 300ms on damage, float damage number popups ("-18", red; "-32 CRIT!", yellow), and trigger a 4-frame screen shake on critical hits. Pure visuals — must not change deterministic battle outcomes.

## Acceptance Criteria

- HP bar width interpolates over 300ms with easeOutCubic.
- Damage popups render via React portal absolute-positioned over the attacker/target slot for 600ms.
- Screen shake using requestAnimationFrame; max offset 6px; auto-resets.
- All visual side-effects gated behind `prefers-reduced-motion: reduce`.
- Test: pure-function damage popup formatter; component renders without crashing.
- `npm test`, `npm run typecheck`, `npm run lint` green.

## Domain Brief

**What**: Make the battle screen feel alive — animate hp bars, float damage numbers, shake on crit — without changing how battles play out.
**Why**: Battles compute correctly but feel static; juice signals impact to the player and makes losses readable. Must not affect deterministic combat math.
**As-Is → To-Be**:
- As-Is: hp width snaps with a 200ms CSS transition; no damage popups; no shake; no JS-side reduced-motion gate.
- To-Be: hp bar tweens 300ms easeOutCubic; damage popups portalled over slots for 600ms; 4-frame rAF shake on crit ≤6px; all JS effects skipped when `prefers-reduced-motion: reduce`.

- Sim is the source of truth — visuals must be a pure consumer of `BattleState`. `BattleState` is mutated only via `executeTurn` (`src/game/Sim/Battle/BattleSim.ts:8`); `rngState` advances inside `computeDamage` (`src/game/Sim/Battle/damageFormula.ts:30`). UI MUST NOT call `rng.*`, mutate any state field, or branch off "did a crit happen" in a way that influences sim inputs.
- Damage events surface today as `state.log` lines `side(0|1) used <Name>: <N> dmg( \(crit\))?` (`src/game/Sim/Battle/BattleSim.ts:60`) and as hp deltas on `state.sides[s].team[activeSlot]`. Both flow through `useBattleStore` (`src/app/stores/battleStore.ts:12`).
- Reduced-motion: global CSS at `src/app/index.css:47` strips `animation`/`transition` — that auto-covers the hp-bar tween. JS-driven popups + shake need an explicit `matchMedia('(prefers-reduced-motion: reduce)')` guard.
- Existing hp-bar tween: `src/ui/screens/BattleScreen.tsx:180` (`transition: width 200ms ease-out`). Change to `300ms cubic-bezier(0.33, 1, 0.68, 1)` to satisfy AC1.
- Test harness: `happy-dom`, no `@testing-library/react`. Use `createRoot` from `react-dom/client` (matches `src/main.tsx:14`).

## Plan Candidates

**What**: Three ways to wire the visual layer to the sim without changing combat math.
**Why**: Each option trades robustness, blast radius, and test cost differently. Plan picks B.

| option | summary | reuse_from | observability |
|--------|---------|------------|---------------|
| A | CSS-only tween + log-regex for both dmg & crit + CSS keyframe shake. Brittle: regex couples UI to log format; shake transform collides with `battleFadeIn`. | src/ui/screens/BattleScreen.tsx:180 | none |
| B | Hybrid: CSS hp-bar tween (300ms easeOutCubic) + JS hp-diff popup detection + log regex for crit flag only + rAF shake on inner wrapper, all JS effects gated by `matchMedia('(prefers-reduced-motion: reduce)')`. | src/ui/screens/BattleScreen.tsx:180, src/main.tsx:14 | none |
| C | New `BattleState.events` array of structured damage events emitted by `BattleSim`. Cleanest UI contract but mutates sim types, perturbs save v3 serialization, violates "pure visuals" spirit. | none | add |

## Recommendation

**What**: Go with Option B (hybrid hp-diff + regex-for-crit, rAF shake on inner wrapper).
**Why**: Smallest blast radius that survives both log-format and sim refactors; obeys "visuals only" by keeping `BattleState` untouched; testable via one pure-function formatter + one render-smoke test.
- Risks accepted: regex still couples to the literal substring "(crit)" in `BattleSim.ts:61` — acceptable because `crit` is the only bit we extract; if the string changes, we lose color tint, not correctness.
- First failing test: `tests/ui/battleScreen.test.tsx` → `formatDamagePopup({ dmg: 32, crit: true })` returns `{ text: '-32 CRIT!', color: 'yellow' }` (test asserts both fields; the formatter does not yet exist).

**Why**: Smallest blast radius that meets all 6 ACs without touching `BattleState`, `BattleSim`, or save format. Keeps the sim deterministic — UI is a pure consumer of `useBattleStore`.
