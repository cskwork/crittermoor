## Description

Players currently lose progress on crashes / refreshes. Add an autosave timer (60 sim-seconds) plus a CRC32 hash on save bytes; on load, verify CRC and reject with a user-friendly error if the bytes are tampered.

## Acceptance Criteria

- Autosave fires every 60 sim-seconds (configurable in settings) under a separate slot `autosave`.
- Save bytes get a CRC32 prefix; `loadSlot` rejects mismatched CRC with a `SaveCorrupt` error.
- A new "recover autosave" button on the title screen when the main slot fails.
- Test fixture: poison a saved blob and confirm `loadSlot` throws `SaveCorrupt`.
- `npm test`, `npm run typecheck`, `npm run lint` green.

## Domain Brief

**What**: Persist progress automatically every minute of in-game time, and refuse to load a save file that has been corrupted.
**Why**: A browser refresh or crash today wipes the colony; silent corruption (partial IDB write, edited export) would otherwise revive a broken world.
**As-Is → To-Be**:
- As-Is: Manual save only, single shared `'autosave'` slot in IDB, `loadGame` trusts whatever bytes come back from `saves` store.
- To-Be: 60 sim-second autosave runs on the sim clock into a separate `autosave` slot; every save is CRC32-tagged and `loadGame` throws `SaveCorrupt` on mismatch; TitleScreen offers a Recover button when an autosave exists.

Save pipeline today: `serialize(sim) → SaveDoc` at codec.ts:26-98, `deserialize(doc) → SimWorld` at codec.ts:100-174, two IDB stores (`saves`, `saveMeta`) via `idb` at store.ts:7-67. Versioning is a top-level `version` field + linear migrations (schema.ts:1-52, migrations.ts:6-30). Sim clock: `TICKS_PER_SECOND_1X = 8`, so 60 sim-seconds = **480 ticks** (constants.ts:3-10); tick rate is independent of `0/1/2/4x` speed, and paused sim does not tick — exactly what we want for autosave cadence. The tick pipeline already uses a hook-options pattern for cross-cutting callbacks (`raid.onRaid`, `jobs.requestPath`, `construct.requestPath` at tick.ts:14-23). Determinism contract `rngState`+`tick` round-trip must survive; see commit `8d92182` for the LE save-endian fix and tests/sim/saves.test.ts:35-45 for the live invariant. **Collision to fix**: HUD's manual save targets the slot literal `'autosave'` (HUD.tsx:12) — AC requires autosave to live in a "separate slot `autosave`", so the manual default must be renamed. No CRC32 helper exists anywhere in the tree (`grep -rn "crc" src/` = 0 hits).

## Plan Candidates

**What**: Three concrete shapes for "where the CRC32 lives" and "how the autosave timer fires"; the rest of the touchpoints (slot rename, Recover button, settings hook) are identical across options.
**Why**: Picking the storage shape now locks the test fixture, the migration story, and the size of the diff.

- **Option A — In-doc `crc` field.** Add `crc: number` at top level of `SaveDoc`; bump `SAVE_VERSION` to 4. Trade-off: smallest types, but "prefix on save bytes" is a field not a prefix, and the canonicalization of the rest-of-doc for hashing is fiddly under JSON property-order drift. Touches schema.ts, codec.ts, migrations.ts, store.ts, tests.
- **Option B — Envelope object `{ crc, doc }` in IDB.** Save wraps the doc; load unwraps + verifies. No `SAVE_VERSION` bump; storage value shape changes once. Trade-off: clean types, but the stored value type silently shifts under the same `saves` keypath — old structured docs must be detected and either rejected or auto-migrated on first load. Touches store.ts, schema.ts, tests.
- **Option C (recommended) — 8-hex-char CRC32 prefix + JSON string in IDB.** Serialize doc to a JSON string, prepend `crc32(jsonBytes).toString(16).padStart(8,'0')`, store the whole string under the `saves` keypath. Trade-off: matches AC ("CRC32 prefix on save bytes") literally; trivial poison test (flip one char); legacy structured docs (pre-CRC) need a one-shot detection branch in `loadGame` to either accept-once or fail with a clear message. Touches store.ts, codec.ts (optional), new crc32.ts, tests.

Autosave timer — all three options use the same approach: extend `SimHooks` in src/game/Sim/tick.ts with `autosave: { onTick: (sim) => void }`, register a single-line system that calls `hooks.autosave.onTick(sim)` after each tick; the `onTick` body checks `sim.tick % intervalTicks === 0` and triggers a debounced `saveGame('autosave', sim)`. Interval seeded from `uiStore.autosaveIntervalSimSeconds` (default 60, written through `setAutosaveInterval`). Reads cleanly under pause and 4x.

_details: docs/CMR-008/explore/notes.md_

## Recommendation

**What**: Option C — prepend an 8-hex-char CRC32 to a JSON-stringified save and store the resulting string in IDB; gate `loadGame` on CRC match; throw a custom `SaveCorrupt` error on mismatch.
**Why**: Closest to the AC wording, smallest test fixture (slice/flip one char), no `SAVE_VERSION` bump (CRC is a storage concern, not a doc-shape concern), and the structured-vs-string discriminator at the store layer is a simple `typeof raw === 'string'` check that lets pre-CRC `'autosave'` records fail loudly with a single user-facing message instead of silently round-tripping unverified bytes.

Risks accepted: (1) browser-quirk JSON key-order drift across engine versions would break the hash — mitigated by the fact that we verify only against our own freshly-written bytes within the same runtime. (2) IDB devtools editing remains trivially possible — out of threat model; CRC catches accidental corruption, not adversaries.

First failing test (write this first, in tests/sim/saves.test.ts): "rejects a poisoned autosave with SaveCorrupt" — `saveGame('autosave', sim)`, open the raw `saves` row from IDB, flip one byte past the 8-char CRC prefix, write it back, and assert `loadGame('autosave')` rejects with `instanceof SaveCorrupt`. Round-trip and CRC-match tests follow.
