## Domain Brief

**What**: 10 first-time milestones that persist on the device (not inside a save) and pop a 4 s toast when unlocked; a "Trophies" tab on the title screen lists them.
**Why**: Players get a long-tail goal log surviving across worlds; reads as polish, not a balance change.
**As-Is → To-Be**:
- As-Is: no `src/achievements/` module; nothing reads/writes any achievement-shaped key in `localStorage`.
- To-Be: `src/achievements/{registry,store,trigger}.ts`, `AchievementToast.tsx`, TitleScreen has Trophies tab, 6 of 10 hooks wired at real trigger sites.

Key invariants the implementer must respect:

- Persistence is **device-scoped, not per-save** (ticket spec). Store must live outside `SimWorld` / `SaveDoc`. Reuse the `try { localStorage } catch {}` pattern at `src/ui/screens/Tutorial.tsx:32,50`.
- `SimWorld` must stay deterministic from seed. Trigger functions must not call `sim.rng.*` or mutate sim state — pure side-effects on a Zustand store + `localStorage`.
- Tame success has exactly one site: `src/game/Sim/Critters/tame.ts:44-50` (return `reason: 'success'`). Wire `onTame(Critter.speciesId[target])` there.
- Build complete: `src/game/Sim/systems/construct.ts:80-89` (state transitions 0→1). Wire `onStructureBuilt()` after `Structure.state[bpEid] = 1`.
- Battle end: `src/game/Game.ts:117-130` (`endBattle(winner)`). To tell raid victories from `startTestBattle`, thread an `isRaid` flag through `startBattle` (only `triggerRaid` at line 88-94 sets it).
- Day check: `dayOf(sim)` at `src/game/Sim/systems/time.ts:15-17`. Evaluate `survived-50-days` and `no-warden-died-50-days` from the HUD's existing 500 ms read loop (`HUD.tsx:34-44`), not inside the deterministic tick.
- Autosave slot label is the literal string `'autosave'` (`HUD.tsx:12`). Pass slot id into `applyLoaded` to gate `autosave-recovered`.
- Three achievements have no upstream system today: `100-meals-cooked` (no cook system), `defeated-a-boss-raid` (raids pick 1-2 random species — no boss concept, `systems/raid.ts:42-45`), and `no-warden-died-50-days` is meaningful only when something writes `Health.downed` on a player warden. Register all 10, only wire 7; document the 3 stubs in the Trophies UI.

## Recommendation

**Option A.** Risk lens won: B couples polish to event-string text (high fragility); C breaks the explicit cross-save persistence requirement and forces an unnecessary save migration. A keeps the sim pure (no RNG calls, no `SaveDoc` change), reuses the proven `localStorage + try/catch` pattern, and the 5 new touch points are each one line.

**Accepted risks:** 3 of 10 achievements (`100-meals-cooked`, `defeated-a-boss-raid`, `no-warden-died-50-days`) ship locked-forever until upstream systems land — registry entries include a `requires` note so the Trophies UI can tag them. We will not fake-fire them.
